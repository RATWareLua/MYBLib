# Численные основы и текстовые форматы

[English](numerics-formats.en.md) | **Русский** · [Все паспорта](index.ru.md)

## Что это

Численный фундамент под всеми моделями и текстовые форматы, в которых приходят данные и уходят
результаты. Элементарные функции корректно округлены (одни и те же биты на любой платформе),
`fma` — собственная; двойная арифметика (double-double), безошибочные преобразования и
компенсированные суммы Sum2/Dot2 держат точность там, где одного double мало; эллиптические
интегралы Карлсона, формы Лежандра и функции Якоби; небольшая плотная линейная алгебра с
постоянным порядком операций. Числа читает корректно округляющий разборщик и печатает точный
печататель — оба не зависят от среды выполнения C и локали. Файлы данных — текстовые ядра NAIF;
таблицы чисел — CSV и родственные записи; орбиты передаются сообщениями CCSDS OEM, OPM, OMM и
OCM в обеих нотациях, KVN и XML.

## Источник

- Корректно округлённые функции: CORE-MATH (P. Zimmermann, A. Sibidanov и др.; MIT), ревизия
  `660067dfd3e751c8f07acc31c899ff410aa7206e`, 19 функций, импортированных
  `third_party/core-math/import.cmake` с тремя механическими правками (путь «невозможного
  трудного случая» в atan2 стал проверкой с немедленной остановкой); их `fma` направлен в
  `myb_fma` — собственную точную реализацию на 128-битной целочисленной арифметике.
- Двойная арифметика и компенсированные суммы: Dekker (1971), Knuth TAOCP т. 2 (1997), Joldes,
  Muller, Popescu (ACM TOMS 44, 2017), Muller & Rideau (ACM TOMS 48, 2022), Ogita, Rump, Oishi
  (SIAM J. Sci. Comput. 26, 2005).
- Эллиптические: дублирование Карлсона (Numer. Algorithms 10, 13, 1995; R_J в форме Карлсона
  1988 г. с R_C), DLMF 19 и 22, A&S 17.7.15 для Π при n < 0.
- Линейная алгебра: балансировка Парлетта–Райнша, приведение к форме Хессенберга и неявный
  QR Фрэнсиса с двойным сдвигом по Golub & Van Loan (алг. 7.5.2), обратные итерации.
- erf и erfc (внутренние, нужны токам зарядки): из `s_erf.c` libm FreeBSD (fdlibm Sun, с
  сохранённым уведомлением SunPro; см. `THIRD_PARTY_NOTICES.md`).
- Разбор: быстрый путь Клингера (PLDI 1990), кандидат в двойной арифметике и точное
  сравнение с серединами на длинных целых; граница в 768 цифр по Lemire (2021). Печать:
  порождение цифр по Стилу и Уайту (PLDI 1990) на длинных целых.
- Текстовые ядра: «Kernel Required Reading» NAIF. CCSDS 502.0-B-2/B-3 (Orbit Data Messages),
  505.0-B (XML Specification for Navigation Data Messages).

## Входы и выходы

- `cmath`: каждая функция возвращает RN(f(x)); особые значения — по IEEE 754 / приложению F
  C; флаги исключений и errno в контракт не входят. Сборка требует binary64 с
  `FLT_EVAL_METHOD == 0`, `-ffp-contract=off` и без fast-math; `test_no_libm_imports`
  проверяет, что библиотека не импортирует ни одной неточной функции libm.
- Числа двойной длины (hi, lo) с hi = RN(hi + lo), около 106 бит; доказанные относительные
  границы (u = 2⁻⁵³): add/sub 3u², add_d 2u², mul 7u², mul_d 1,5u² + 4u³, div 15u² + 56u³,
  div_d 3,5u²; у sqrt (одна поправка Карпа–Маркштейна) опубликованной границы нет, тесты
  требуют < 4u². Варианты без FMA — сознательно (у базового x86-64-v2 нет аппаратного FMA).
  `myb_two_prod` точен без переполнения и при e_a + e_b ≥ −970.
- Sum2: |результат − S| ≤ u|S| + γ²ₙ₋₁ Σ|xᵢ|; Dot2: ≤ u|x·y| + γ²ₙ |x|·|y|; порядок —
  пользователя, поэтому результат детерминирован.
- Эллиптические: x, y, z ≥ 0, не более одного нуля, p > 0; m = k² ≤ 1, n < 1; неполные формы —
  для любого вещественного φ через квазипериодичность; Якоби — для 0 ≤ m ≤ 1.
- Линейная алгебра: матрицы по строкам порядка n ≤ 64, постоянный порядок операций (одни и те
  же биты везде); функции держат собственный стек ниже 1 КБ.
- `myb_parse_double`: десятичные (с показателями `eEdD`), шестнадцатеричные, `inf`, `infinity`,
  `nan`; ведущие пробелы не пропускаются; десятичный разделитель — всегда '.'; округление к
  ближайшему, половина к чётному, переполнение — в бесконечность, плавная потеря значимости;
  хранится 800 значащих цифр, дальше — флаг «липкого» бита.
- Печать: кратчайшая запись, читаемая обратно (вид `repr` Python, позиционная при
  10⁻⁴ ≤ |x| < 10¹⁶, не длиннее 24 символов); `decimals` 0–60 как `%.Nf`; `digits` 1–60 как
  `%.(digits−1)e`; половина к чётному; полная длина сообщается всегда.
- Таблицы: запятые, точки с запятой, табуляции или пробелы; комментарии `#`; первая строка не
  из чисел — имена столбцов (хранится 31 символ); пустое поле — NaN; запись кратчайшими
  записями, не более 1024 столбцов.
- Ядра: `NAME = value`, `NAME = ( … )`, `NAME += ( … )` внутри `\begindata … \begintext`;
  фортрановские показатели `D`; строки в одинарных кавычках; @-даты хранятся строками;
  загрузка атомарна; пути — UTF-8; собственные ядра JPL (`gm_de440.tpc`, `pck00011.tpc`)
  читаются без переделки.
- CCSDS: в файле км, км/с, км/с², градусы, км³/с²; в API — СИ (средние элементы OMM остаются в
  единицах сообщения: они осмысленны только вместе со своей теорией). Эпохи — календарные метки
  на `TIME_SYSTEM` сообщения, переводит их пользователь. Ковариации — 6 × 6 по строкам (в файле
  нижний треугольник). Читатель узнаёт нотацию по первому символу ('<' — XML). Число пишется
  кратчайшей десятичной записью в единицах файла, которую читатель превращает в то же значение
  СИ; секунды эпох — столько знаков, сколько нужно, не меньше трёх. OEM пишется версии 2.0,
  OCM — версии 3.0. Писатели не выделяют память: текст идёт в буфер вызывающего.

## Область применимости

- Операции двойной длины требуют конечных аргументов и результатов без переполнения и потери
  значимости. Эллиптические аргументы вне своих областей дают NaN.
- Линейная алгебра: `MYB_E_DOMAIN` для вырожденной, не положительно определённой, неполного
  ранга или неконечной матрицы; `myb_eigenvalues` даёт `MYB_E_NOCONV` после 30 n проходов.
- Разбор: `MYB_E_FORMAT`, если с этого места число не начинается (выходы не тронуты).
- Печать: `MYB_E_DOMAIN` для числа знаков или цифр вне диапазона, `MYB_E_OVERFLOW` для
  короткого буфера (текст обрезан, но завершён).
- Таблицы и ядра: `MYB_E_FORMAT` (diag называет строку), `MYB_E_NOMEM`, `MYB_E_OVERFLOW`,
  `MYB_E_IO`; запросы к ядрам — `MYB_E_NOT_FOUND`, `MYB_E_FORMAT` (не тот тип), `MYB_E_RANGE`
  (номер строки).
- Читатели CCSDS: `MYB_E_FORMAT` (diag называет строку: не то сообщение, нет обязательного
  ключа, плохое число или дата, больше 16 манёвров OPM); писатели — `MYB_E_DOMAIN` (нет
  сегментов, нет текста, неконечные значения, неверные даты) и `MYB_E_OVERFLOW` (повторить с
  length + 1 байтами); `myb_ocm_state` даёт `MYB_E_DOMAIN` для `TRAJ_TYPE`, отличного от
  CARTP, CARTPV, CARTPVA.

## Ограничения

- Среди корректно округлённых функций нет `pow` (отложена в фазе 2); erf и erfc — внутренние,
  в открытый заголовок не входят.
- У квадратного корня двойной длины нет опубликованной границы ошибки; его ограничивает только
  выборка тестов.
- Линейная алгебра — для небольших систем (n ≤ 64) собственных решателей библиотеки.
- XML сообщений CCSDS: читаются элементы и атрибуты сообщений, значение может быть одним
  разделом CDATA, объявление типа с внутренним подмножеством пропускается — но объявленные в
  нём сущности неизвестны (`&name;` остаётся как написано); раздел CDATA вперемешку с текстом,
  два раздела подряд и незавершённый раздел — отказ.
- Комментарии и пользовательские ключи OEM, OPM, OMM пропускаются. OCM отдаётся как есть —
  ключи по имени, строки текстом и числами в единицах сообщения; в СИ — только декартовы
  траектории.
- Перевод эпох сообщения на шкалу времени — дело пользователя
  ([шкалы времени](time-scales.ru.md)).
